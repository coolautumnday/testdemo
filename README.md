# AI 多智能体网页生成器

> 
> 模仿 Atoms 多 Agent 设计，**产品 Agent 做需求拆解 → 工程师 Agent 生成网页 → 自动测试评审 → 自动修复 bug**，三栏式网页 IDE，浏览器端直接调用大模型 API 生成可交互 HTML 网页。

## ✨ 主要特性

1. 🧩 **多智能体链路**
   - 产品 Agent：独立 LLM 调用，对用户需求结构化分析，输出需求报告；
   - 工程师 Agent：基于产品报告生成完整内嵌式 HTML，全部 CSS/JS 内联，无外部依赖；
   - 测试评审 Agent：自动代码评审，识别语法、交互、业务逻辑、NaN 等风险；
   - 自动修复：检测🔴高风险缺陷自动修复，设置最大修复轮次，防止死循环。
2. 📝 **三栏界面布局**
   - 左侧：对话面板，多 Agent 动画状态展示，聊天交互；
   - 中间：代码编辑器，实时编辑 HTML；
   - 右侧：iframe 实时预览，所见即所得。
3. 🛡️ **多层缺陷防护**
   - JS 语法预检：使用`Function`构造器捕获 JS 语法错误；
   - iframe 运行时监控：MutationObserver 捕获页面渲染`NaN`文本，捕获 JS 运行异常、Promise 异常；
   - 评审标记区分高 / 中 / 低风险，仅高风险触发自动修复；
   - 截断兼容：模型输出截断时，尽可能提取可用代码，给出告警。
4. 🎨 UI 交互能力
   - 可拖拽分割条，自由调整三栏宽度；
   - 打字机动画输出思考、报告内容；
   - 会话本地持久化（localStorage），刷新页面不丢失；
   - 导出 HTML 文件；
   - 手动代码评审按钮，可对已有代码执行评审；
   - API Key 本地存储，不会上传服务器。
5. ⚠️限制说明
   - 仅做语法 + LLM 评审，**无法 100% 识别业务逻辑错误**；
   - JS 内部变量 NaN 但不渲染到 DOM，运行时监控无法捕获，依赖 AI 评审；
   - 每次发送至少消耗 2 次 LLM 请求（产品分析 + 代码生成），修复会继续消耗 token；
   - 浏览器直接调用智谱 API，注意网络跨域问题。

## 📦 运行方式

1. 将全部代码保存为 `index.html`；
2. 使用浏览器直接打开该文件（不需要后端服务，纯前端单文件）；
3. 输入你的**智谱 AI API‑Key**，进行验证；
4. 在左侧输入框输入网页需求，点击发送。

## 🚀 使用流程示例

1. 用户输入需求：`做一个2048网页小游戏`
2. UI 显示：`产品 Agent 正在拆解需求`，大模型输出结构化需求分析报告；
3. UI 切换：`工程师 Agent 正在写代码`，依据产品报告生成完整 HTML；
4. JS 语法预检，聊天框输出预检结果；
5. 渲染代码编辑器 + iframe 预览；
6. 自动执行代码评审，如果存在🔴高风险 bug，进入自动修复循环（最多 3 轮）；
7. 如果预览页面渲染出`NaN`，聊天框弹出🔴运行时告警；
8. 可以点击【AI 代码评审】按钮，手动对当前编辑器代码执行评审；
9. 点击【导出 HTML】保存生成结果。

## 🧠 内部 SystemPrompt 说明

1. `productAgentSystemPrompt`：产品经理 Agent，做需求结构化拆解；
2. `systemPrompt`：工程师 Agent，生成完整 HTML 网页；
3. `testReviewSystemPrompt`：软件测试 Agent，代码评审，识别语法、交互、NaN 风险；
4. `fixCodeSystemPrompt`：修复 Agent，根据评审报告修复网页缺陷。

## 🐛 已知局限

1. 属于**前端纯客户端应用**，密钥保存在浏览器 localStorage，不要对外部署；
2. LLM 幻觉问题：评审与修复都依赖大模型，存在漏报、误报、越修越坏的可能性；
3. 运行时监控只能捕获**DOM 上可见的 NaN 文本**，JS 内存内部 NaN 无法捕获；
4. 每轮请求会携带完整会话历史，会话过多会增加 token 消耗，建议频繁点击新建会话。

## 💡扩展开发建议

1. 增加开关复选框：允许用户关闭产品 Agent 需求分析，减少 token 消耗；
2. 改造为 SSE 流式接口，实现流式逐字输出思考与代码；
3. 增加后端代理层，避免前端暴露 API 密钥；
4. 增加更多运行时检测：DOM 异常、样式问题检测；
5. 增加导入已有 HTML 文件功能。
